Hear your keyboard
the way you wish it sounded.

KeyVibes plays a mechanical switch sound on every key press, straight from the kernel's evdev interface to your speakers. No root, no keylogger, no input injection — one background process and a sound pack.

Built around one rule

The path from key press to speaker must never do anything that can block. That rule decides where the locks are, what the real-time thread is allowed to touch, and why packs are memory-mapped files rather than parsed structures.

Latency

Nothing blocks the audio path

A lock-free SPSC queue feeds a 32-voice mixer. The real-time callback takes zero locks, allocates nothing, and performs no I/O.

Privacy

Not a keylogger

Key codes choose a sound and are then forgotten. No key code is ever written to a log, a file, or a socket.

Safety

Not an input remapper

KeyVibes never modifies, blocks, or injects key events. It reads them, plays a sound, and hands them straight through.

Access

No root, no desktop dependency

It reads /dev/input and talks to your user's PipeWire socket — what a normal user can already do. Works on X11 and Wayland alike, because it needs neither.

Audio

Real-time, measured

Cubic-interpolated voices, oldest-first voice stealing, and a real-time limiter. Sub-5µs render times on a full 32-voice mix.

Desktop

A window when you want one

The engine is headless by design. A GTK4/libadwaita app sits beside it for browsing packs, adjusting settings, and running diagnostics — and quits without leaving the engine behind.

Sound packs

A pack is a directory with a manifest and a WAV per key. Three synthesized packs ship with KeyVibes; upstream packs drop into the same folder.

Default

synth

Modeled linear-switch press for all 104 keys, two variants per key. The pack KeyVibes starts with.

Holy Panda

synth

A tactile bump with a rounded bottom-out — the clicky-adjacent crowd's reference switch.

Buckling Spring

upstream

The Model M ring: a metallic buckling snap, recorded rather than modeled.

Preview audio on this page is synthesized in the browser and is only a taste. The real packs ship with release clips, per-key variation, and optional spatialization.

Install

Two commands to a running engine, or build it yourself.

Get a package

Debian/Ubuntu, Fedora/openSUSE, Arch, or a portable archive — pick your flavour.

# Debian / Ubuntu
sudo apt install ./keyvibes_0.1.0_amd64.deb

Run it

The engine is headless. Start it, then open the app if you want a window.

keyvibes run &
keyvibes-ui

Check it

One command drives the whole flow from launch to speakers.

keyvibes acceptance-test

Or build from source

Needs Rust, GTK 4 and libadwaita development packages.

git clone https://github.com/IndraJeet-09/keyvibes
cd keyvibes && cargo build --release
cargo run -p keyvibes -- acceptance-test

Honest about what it is not

Not a remapper

It cannot change what your keys do.

Not a keylogger

Nothing you type is stored or transmitted.

Not root

No setuid binary, no daemon running as another user.

Not tied to a desktop

No X11, no Wayland, no toolkit in the engine's dependency graph — enforced by an audit.
